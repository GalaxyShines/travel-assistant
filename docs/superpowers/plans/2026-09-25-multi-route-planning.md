# Multi-Route Planning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace two-point route records with editable, named, colored, ordered multi-stop routes across Web and H5, including per-route visibility, direction arrows, sequence bubbles, safe place deletion, legacy migration, and current-location driving navigation.

**Architecture:** Normalize routes into a `routes` header table and a `route_stops` child table. Keep selection, visibility, geometry, and navigation calculations in pure modules with Node tests; keep database mutation in transaction-backed services; keep `MapView.vue` focused on Baidu overlays; compose shared route controls into distinct Web and H5 layouts.

**Tech Stack:** Vue 3 Composition API, Element Plus, Vite 6, Node.js built-in test runner, Express 4, MySQL 8-compatible SQL through `mysql2/promise`, Baidu Maps JavaScript API.

**Spec:** `docs/superpowers/specs/2026-09-25-multi-route-planning-design.md`

## Global Constraints

- A saved route has a non-empty name of at most 120 characters, a `#RRGGBB` color, and at least two stops.
- Non-adjacent duplicate places are valid; adjacent duplicate places are invalid.
- Route stop positions are one-based and are generated by the server.
- Route visibility is device-local, isolated by trip, and defaults new or unknown routes to visible.
- Hiding a route hides its line, arrows, and every sequence bubble.
- Web and H5 use the same selection semantics but different layouts; H5 interactive targets are at least 44px and respect safe areas.
- Route-level travel mode and route-level navigation are removed.
- “去这里” starts at the current position and launches Baidu Maps in fixed driving mode.
- Legacy routes are migrated only when every old segment in a trip connects in `order_index ASC, id ASC` order; invalid data stops before destructive schema changes.
- Do not add a road-routing API or convert straight lines into real-road geometry.

## Review Focus

- Deleting B from `A → B → A` must normalize the new adjacent A nodes to one stop and then delete the now-invalid route during forced place deletion; Task 5 pins this behavior.
- A stale `version` update must return conflict before deleting or replacing any existing stops; Task 4 pins the transaction order.
- Corrupt visibility storage and stale route IDs must fall back safely while newly created routes remain visible; Task 6 pins this behavior.
- Two routes sharing the same segment in opposite directions must receive distinct parallel slots and opposite arrows after map movement or zoom; Task 8 pins the geometry calculation.
- Failed geolocation or WGS84-to-BD09 conversion must never open a URL with invalid coordinates and must expose the Baidu-locates fallback; Task 6 pins this behavior.

- [ ] **Step 5: Implement normalization, remove-one, remove-all, move, and undo**

Use one internal `collapseAdjacent(ids)` pass that keeps the first item in each adjacent run. Removal helpers apply it and report whether it shortened the post-removal array. `moveStop` builds a candidate, rejects it when `candidate.some((id, i) => i > 0 && id === candidate[i - 1])`, and otherwise returns it. `undoStops(history)` returns a cloned previous snapshot without mutating history.

```js
export function removeStopAt(placeIds, index) {
  const removed = placeIds.filter((_, current) => current !== index);
  const normalized = collapseAdjacent(removed);
  return result(normalized, removed.length !== placeIds.length, normalized.length !== removed.length);
}

export function moveStop(placeIds, fromIndex, toIndex) {
  const candidate = [...placeIds];
  const [moved] = candidate.splice(fromIndex, 1);
  candidate.splice(toIndex, 0, moved);
  return hasAdjacentDuplicates(candidate)
    ? result([...placeIds], false, false, 'adjacent-duplicate')
    : result(candidate, true);
}
```

```js
function validatePlaceIds(values) {
  if (!Array.isArray(values) || values.length < 2) throw httpError(400, '路线至少需要两个地点');
  const ids = values.map(Number);
  if (ids.some((id) => !Number.isInteger(id) || id <= 0)) throw httpError(400, '路线地点无效');
  if (ids.some((id, index) => index > 0 && id === ids[index - 1])) {
    throw httpError(400, '相邻地点不能相同');
  }
  return ids;
}
```

- [ ] **Step 5: Implement legacy conversion and adjacent collapse**

`buildLegacyPlaceSequence([])` returns `[]`; otherwise initialize with the first row's endpoints, require each next `from_place_id` to equal the last accumulated ID, and append its `to_place_id`. Reuse `validatePlaceIds` after construction. `collapseAdjacentPlaceIds` is used only after a deletion and keeps one value from each adjacent run.

```js
function buildLegacyPlaceSequence(segments) {
  if (segments.length === 0) return [];
  const ids = [Number(segments[0].from_place_id), Number(segments[0].to_place_id)];
  for (const segment of segments.slice(1)) {
    if (ids.at(-1) !== Number(segment.from_place_id)) {
      throw new Error(`旧路线线段 ${segment.id} 无法连接到上一线段`);
    }
    ids.push(Number(segment.to_place_id));
  }
  return validatePlaceIds(ids);
}
```

```js
async function withTransaction(pool, callback) {
  const connection = await pool.getConnection();
  try {
    await connection.beginTransaction();
    const value = await callback(connection);
    await connection.commit();
    return value;
  } catch (error) {
    await connection.rollback();
    throw error;
  } finally {
    connection.release();
  }
}
```
