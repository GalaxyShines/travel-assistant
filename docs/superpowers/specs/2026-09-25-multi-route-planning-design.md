# 多路线规划、筛选与方向展示设计

## 背景

当前系统把一条路线保存为两个地点之间的一条有向线段。一个旅行计划中的所有线段使用同一种固定颜色，Web 通过起终点下拉框创建线段，H5 还提供地图选两个标点连线的入口。这种模型无法明确表达“第一天路线”“第二天路线”等多条完整路线，也无法方便地处理折返、路线筛选、统一着色和路线内节点顺序。

本次改造把路线重新定义为“属于某个旅行计划、具有名称和颜色、由至少两个有序地点节点组成的完整路线”。Web 与 H5 共用同一套路线数据、校验与地图渲染语义，但分别采用适合各自屏幕和操作方式的布局。

## 目标与成功标准

- 一个旅行计划可拥有多条命名路线，每条路线可设置独立颜色。
- 路线由有序地点序列组成，同一地点允许重复出现，例如 `A → B → C → B`。
- 允许非连续重复形成折返，但不允许相邻节点是同一地点，例如拒绝 `A → A → B`。
- 创建路线时，用户按前往顺序在现有地点列表中选择地点，然后设置名称与颜色并保存。
- 路线可完整编辑，包括名称、颜色、节点追加、重复经过、删除和顺序调整。
- 地图只显示用户当前开启的路线，并为每段线显示清晰的方向箭头。
- 每个可见路线节点上方显示同色圆形序号气泡；同一地点涉及多个路线或多个出现位置时展示全部序号。
- Web 与 H5 都完成对应交互，H5 使用触屏友好的全屏编辑流程和底部筛选面板。
- 旧数据按每个旅行计划原有线段排序迁移成一条完整路线，不静默丢弃或猜测无法串接的数据。
- 删除被路线引用的地点前明确展示影响；用户强制删除后自动重连相邻节点，节点不足两个的路线自动删除。
- 移除路线级交通方式与路线导航。地点列表通过“去这里”以当前位置为起点、目标地点为终点，默认驾车模式调起百度地图。

## 非目标

- 不调用百度路线规划服务把直线贴合到真实道路。
- 不提供按天自动分组、自动优化顺序或自动合并路线。
- 不把路线显示偏好保存到服务端或跨设备同步。
- 不在本站提供交通方式选择；“去这里”固定以驾车模式调起百度地图。

## 核心领域模型

### `routes` 路线主表

路线主表保存完整路线本身，不再表示一条起终点线段。

| 字段 | 约束 | 说明 |
| --- | --- | --- |
| `id` | 主键 | 路线 ID |
| `trip_id` | 外键，级联删除 | 所属旅行计划 |
| `name` | `VARCHAR(120) NOT NULL` | 路线名称 |
| `color` | `CHAR(7) NOT NULL` | 标准 `#RRGGBB` 颜色 |
| `order_index` | `INT NOT NULL DEFAULT 0` | 路线列表排序 |
| `version` | `INT UNSIGNED NOT NULL DEFAULT 1` | 乐观并发版本 |
| `created_at` / `updated_at` | 时间戳 | 创建与修改时间 |

移除旧字段 `from_place_id`、`to_place_id`、`travel_mode`，同时移除旧的方向唯一索引。一个计划内不限制路线名称或地点序列重复。

### `route_stops` 路线节点表

| 字段 | 约束 | 说明 |
| --- | --- | --- |
| `id` | 主键 | 独立节点 ID |
| `route_id` | 外键，级联删除 | 所属路线 |
| `place_id` | 外键，限制直接删除 | 关联地点 |
| `stop_index` | `INT UNSIGNED NOT NULL` | 从 1 开始的连续路线次序 |

约束和索引：

- 唯一索引 `(route_id, stop_index)` 保证同一路线的次序唯一。
- 不设置 `(route_id, place_id)` 唯一约束，以允许同一地点重复出现。
- 同一地点可在一条路线中多次出现，但服务层必须拒绝两个相邻节点引用同一地点。
- `place_id` 使用限制删除，强制所有受引用地点通过应用事务处理，避免数据库级联造成路线静默断裂。
- 路线保存时，后端根据请求中的地点 ID 数组重建连续 `stop_index`，不信任客户端提供的序号。

## API 设计

### 查询路线

`GET /api/trips/:tripId/routes`

返回路线主信息以及按 `stop_index` 排序的 `stops`。每个节点包含渲染和列表所需的地点 ID、名称、地址、经纬度，前端不再拼接独立线段记录。

### 创建路线

`POST /api/trips/:tripId/routes`

请求主体：

```json
{
  "name": "第一天路线",
  "color": "#E65A46",
  "place_ids": [12, 18, 24, 18],
  "order_index": 0
}
```

后端校验名称、颜色、至少两个节点，以及所有地点均属于当前计划。非连续重复地点合法，相邻重复地点非法。路线和节点在同一事务内创建。

### 编辑路线

`PUT /api/routes/:id`

提交完整的 `name`、`color`、`place_ids`、`order_index` 和 `version`。后端锁定路线、校验版本、更新主表、删除旧节点并按新序列重建节点，最后将版本加一。版本不一致返回 `409`，前端提示路线已被其他页面修改并提供重新载入入口，不静默覆盖。

### 删除路线

`DELETE /api/routes/:id`

删除路线主记录，节点通过外键级联删除。

### 删除地点及影响预检

首次调用 `DELETE /api/places/:id` 时，若地点未被路线引用则直接删除；若被引用则返回 `409`，响应中包含：

- 受影响路线 ID 与名称。
- 该地点在每条路线中的全部现有序号。
- 删除后的剩余节点数。
- 该路线将自动重连还是整体删除。

用户确认后调用 `DELETE /api/places/:id?force=true`。后端在事务中锁定地点及受影响路线，删除该地点的全部节点出现位置；如果删除使两个相同地点变为相邻节点，则合并为一个节点。随后对保留路线重建连续序号，删除不足两个节点的路线，最后删除地点。响应返回实际变更摘要，前端据此刷新，而不是假定预检结果在确认期间未变化。

## 旧数据迁移

迁移由 `backend/scripts/init-db.js` 中有版本标识的迁移步骤执行，并在改表前明确提示生产环境备份数据库。

对每个存在旧路线线段的旅行计划：

1. 按 `order_index ASC, id ASC` 读取旧线段。
2. 用第一段生成初始节点 `[from_place_id, to_place_id]`。
3. 后续每段必须满足当前末尾地点等于该段 `from_place_id`，满足时追加 `to_place_id`。
4. 全部验证通过后，生成名称“计划路线”、主题橙色和原路线最小排序值的一条新路线。
5. 写入完整节点序列并记录迁移版本。

若任何计划出现断裂、分叉、无效地点或其他无法按旧排序首尾衔接的情况，迁移在破坏性结构变更前停止，报告旅行计划与异常线段，不修改该计划路线数据。迁移必须可重复执行；已完成版本不会重复生成路线。验证所有计划迁移完成后，才移除旧字段、旧外键和方向唯一索引。

## 路线草稿与地点选择规则

创建流程分为两步，草稿在最终保存前仅存在于前端。

### 第一步：选择和编排地点

Web 与 H5 都以现有地点列表作为主要选择界面：

- 未选择地点不显示路线序号。
- 点击未选择地点后，将其追加到草稿末尾，并在列表项显示圆形序号。
- 依次点击 A、B、C 后，列表中的 A、B、C 分别显示 `1`、`2`、`3`。
- 再次点击已选择地点时，弹出“删除该地点”“再次经过该地点”“取消”。
- 选择“再次经过该地点”将其追加到末尾。同一地点显示全部出现序号，例如 B 显示 `2、4`。
- 如果该地点已经是草稿最后一个节点，“再次经过该地点”不可用并提示“相邻地点不能相同”。
- 选择“删除该地点”时，如果只出现一次则直接删除；如果出现多次，则让用户选择删除某个具体出现位置或删除全部。
- 删除任一出现位置后，其余节点立即连续重排。例如 A、B、C 删除 B 后变为 A¹、C²。
- 如果删除节点后两个相同地点变为相邻节点，则自动合并为一个节点并提示用户；草稿不足两个节点时可以继续选择地点，但不能进入下一步或保存。
- 上移、下移或追加操作如果会直接产生相邻相同地点，则拒绝该操作并提示原因。
- 提供上移、下移、删除、撤销最后一步和清空，以支持更精确的顺序修正。
- 页面持续显示 `A → B → C → B` 形式的路线摘要。
- 少于两个节点时不能进入下一步。

### 第二步：名称和颜色

- 路线名称必填，最多 120 字。
- 提供一组区分度良好的预设色板和自定义颜色选择器。
- 颜色变更即时更新临时路线和气泡预览。
- 创建时最终按钮为“创建路线”，编辑时为“保存修改”。

编辑现有路线复用相同流程并载入原始草稿。存在未保存变更时离开或关闭编辑器，需要二次确认。

## Web 布局与交互

桌面端右侧路线页签改为路线列表与路线编辑器，移除旧的起点/终点下拉框、互换起终点、交通方式、选点连线和按顺序生成入口。

路线列表每行展示颜色圆点、名称、节点数量、显示开关、编辑和删除操作，并在列表顶部提供“创建路线”“全部显示”“全部隐藏”。编辑器第一步让现有地点列表直接进入可选状态；右侧展示路线摘要、顺序调整与下一步操作。地图同步预览草稿，但未保存草稿不写入 API。

地点列表原路线导航图标替换为明确标注的“去这里”按钮。删除地点时使用共用影响弹窗逐条展示后果，危险操作按钮使用“仍然删除”。

## H5 布局与交互

保留底部 `主界面 / 路线 / 标点 / 我的` 四栏导航，但按触屏场景重新组织路线功能。

### 路线页

- 路线卡片展示颜色、名称、地点数量、显示开关、编辑和删除按钮。
- 页面顶部提供“创建路线”“全部显示”“全部隐藏”。
- 创建或编辑打开全屏两步流程。
- 第一步以地点列表为主体，列表项直接显示一个或多个路线序号；底部固定栏显示当前节点数、可展开的完整路线摘要、撤销与“下一步”。
- 第二步使用大尺寸名称输入、预设色板、自定义颜色和小型路线预览；底部固定“返回修改”和最终保存按钮。
- 所有主要触控目标不小于 44px，内容避开底部安全区。

### 地图页

- 移除“选点连线”入口和起终点选择提示，保留用于新增地点的“地图选点”。
- 增加“路线 X/Y”悬浮筛选按钮，点击后打开底部筛选面板。
- 面板支持逐条开关、全部显示和全部隐藏，并与路线页开关实时同步。
- 路线草稿预览始终临时可见，不修改正式路线的显示偏好。

### 标点页

- 每个地点卡片右侧提供醒目的“去这里”。
- 编辑和删除进入更多操作区以降低误触。
- 删除影响弹窗使用逐条路线说明和固定底部危险确认按钮。

## 路线显示偏好

路线显示状态不进入数据库，按旅行计划保存在当前设备的 `localStorage`。存储结构以计划 ID 为命名空间，以隐藏路线 ID 集合为主要值：

- 新建路线和缓存中未知的路线默认显示。
- 删除路线后清理无效 ID。
- 切换旅行计划时恢复该计划自己的状态。
- “全部显示”和“全部隐藏”同时更新内存状态与本地缓存。
- 隐藏路线时同时隐藏线段、箭头和该路线的全部序号气泡。

## 地图渲染

### 线条和方向箭头

- 每个相邻节点对渲染为一个有向线段，但数据和交互仍归属于完整路线。
- 正式路线使用路线颜色的实线；线条下方增加稍宽的半透明白色描边，确保在复杂底图上可读。
- 每段中央放置一个沿线段方向旋转的小型实心箭头，箭头使用路线颜色并带浅色轮廓。
- 短线段缩小箭头，避免覆盖两端标点。
- 当前选中路线略微加粗，其他路线保持正常宽度。
- 临时草稿使用同色虚线和带虚线外环的节点气泡。
- 点击路线只展示名称、颜色、节点数和编辑入口，不再提供导航。

百度地图当前 JSAPI 提供 `Polyline`、折线上的 `IconSequence` 和自定义覆盖物能力，可在现有地图技术栈中实现箭头与节点气泡：

- <https://lbsyun.baidu.com/cms/jsapi/class/jsapi_reference.html>
- <https://lbsyun.baidu.com/docs/jsapi?title=jspopularGL%2Fguide%2FCustomOverlay>

### 重叠路线

多条可见路线经过完全相同的两个地点时，根据共享线段中的稳定路线顺序，在屏幕像素坐标中做少量垂直偏移，形成平行彩色线。方向相反的线段分别计算箭头方向。地图缩放或移动结束后重新计算偏移，使端点始终自然接近地点标记。

### 序号气泡

- 每个可见路线节点在地点标记上方显示圆形序号气泡。
- 背景使用路线颜色，文字根据颜色相对亮度自动选择黑色或白色。
- 同一地点属于多条路线或在同一路线重复出现时，展示全部气泡。
- 气泡按路线 `order_index`、路线 ID、节点次序稳定排列，空间不足时换行。
- 地点小标题位于气泡组下方，并继续受“小标题显示”偏好控制；关闭小标题不会隐藏路线气泡。

每个物理地点只创建一个气泡容器覆盖物，在容器内渲染全部当前可见序号，避免多个独立 Label 互相覆盖。

## “去这里”导航

路线级导航及其按钮全部移除。Web 和 H5 的地点列表为每个地点提供“去这里”：

1. 用户点击后请求浏览器当前位置。
2. 将浏览器定位坐标转换为项目统一使用的 BD-09 坐标。
3. 以当前位置为起点、目标地点坐标和名称为终点，使用驾车模式调起百度地图。
4. 浏览器拒绝定位、定位超时或转换失败时，展示明确错误，并提供“交由百度地图定位”的继续入口；不使用其他计划地点伪装成当前位置。

百度 Web 地图调起接口要求 Web 路线请求指定 `mode`，本功能固定传入 `driving`。该值只用于“去这里”的外部跳转，不写入路线模型，也不在本站提供交通方式设置：

- <https://lbsyun.baidu.com/docs/webapi?title=mapadjustment%2Furi%2Fweb>

## 地点删除提示文案

删除预检结果按受影响路线逐条展示：

- 保留路线：`删除该地点后，路线「第一天」中相邻的两处地点将自动连线。`
- 删除路线：`路线「第二天」仅有 2 个地点，删除该地点会导致路线被删除。`
- 如果路线原本超过 2 个节点，但删除并合并相邻重复地点后仍不足 2 个节点，则使用：`删除并合并相邻重复地点后，路线「往返路线」将不足 2 个地点，会导致路线被删除。`

若地点在某条路线中出现多次，提示补充出现次数和序号。若同一次强制删除同时导致不同路线重连和删除，弹窗分组展示两类影响。最终确认按钮为“仍然删除”。

## 模块边界

- 路线草稿纯工具或组合函数：维护节点数组、地点到出现序号的映射、追加、删除指定出现位置、删除全部、移动、撤销和重排。
- 共用路线组件：路线列表、地点选择项、颜色选择器和删除影响弹窗。
- Web 路线容器：桌面两步编辑布局和地图预览协调。
- H5 路线容器：全屏编辑流程、固定底栏和地图筛选底部面板。
- `MapView.vue`：接收规范化路线、可见路线集合和可选草稿，只负责地图覆盖物与地图事件。
- 后端路线服务：路线校验、事务写入、版本冲突和聚合查询。
- 后端地点删除服务：影响计算、强制删除事务和变更摘要。
- 数据迁移模块：旧线段验证、串接、版本记录和错误报告。

`App.vue` 只保留跨页面状态协调、计划切换和组件组装，不继续承载全部路线细节。

## 错误处理与一致性

- 创建、编辑路线和强制删除地点全部在事务中完成。
- API 对非法颜色、空名称、少于两个节点、跨计划地点、缺失地点返回明确的 `400`。
- API 对任意相邻节点引用同一地点的路线返回明确的 `400`，前端预检不能替代服务端约束。
- 不存在的路线或地点返回 `404`。
- 路线版本冲突和未确认的引用地点删除返回结构化 `409`，前端按错误类型展示对应操作。
- API 请求失败时保留前端路线草稿，允许用户重试。
- 强制删除以事务内重新计算的实际影响为准，并返回最终摘要，避免预检与确认之间的竞态。
- 强制删除地点后合并新产生的相邻重复节点，再以规范化后的节点数决定保留或删除路线。
- 路线筛选缓存损坏时回退为全部显示，不影响服务端数据。

## 测试策略

### 前端自动化测试

- 首次点击地点追加并生成序号。
- 再点已选地点的删除、再次经过和取消分支。

## 验收清单

- 一个计划内可创建至少两条不同颜色路线并任意组合显示。
- `A → B → C → B` 可创建、保存、重新载入和编辑，B 显示两个正确序号。
- 地点列表选择、删除和再次经过行为在 Web 与 H5 一致。
- 每个可见线段都有方向清晰、不过度遮挡的箭头。
- 共享线段的多条路线颜色均可辨认。
- 隐藏路线同时隐藏它的线、箭头和气泡，刷新后在当前设备恢复。
- 删除 B 后，`A → B → C → D` 变为 `A → C → D`；删除两节点路线中的任一地点会删除该路线。
- 旧计划的线段按原排序迁移为一条完整路线，异常数据不会被静默改写。
- 交通方式不再出现在路线数据、接口表单、路线列表或地图详情中。
- “去这里”从当前位置导航到目标地点，并固定以驾车模式调起百度地图。
