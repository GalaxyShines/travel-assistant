# 旅行规划地图 H5 适配设计

## 目标与范围

将现有 Vue 旅行规划地图改造成兼容桌面与 H5 的双布局应用。桌面端继续使用现有三栏工作区；在手机视口下提供面向旅行途中单手操作的移动端体验，且不减少已有的计划、标点、路线、搜索与百度导航能力。

移动端的核心场景是：用户没有电脑时，能查看已规划的路线和地点，并随时新增、编辑或删除地点和路线。

不在本次范围内：账户体系变更、路线真实道路规划、地图供应商替换、地点数据模型扩展。

## 信息架构与导航

手机视口（沿用项目现有的 760px 响应式断点）启用 H5 外壳。底部固定四个一级入口：

1. **主界面**：地图浏览、搜索、地图选点、地图选点连线、地图显示开关。
2. **路线**：当前计划的路线列表、新增、编辑、删除和百度导航。
3. **标点**：当前计划的标点列表、新增、编辑、删除和百度导航。
4. **我的**：旅行计划切换、新增、编辑、删除和退出登录。

移动端顶栏持续展示当前计划名称，并提供计划切换入口。页面切换不重载计划数据、不丢失地图中心点，也不清空未保存的编辑内容，除非用户主动关闭编辑界面。

桌面端不引入底部导航，维持三栏布局和已有操作入口。移动端与桌面端使用同一数据源和 API。

## 主界面与地图交互

主界面以百度地图为核心内容：

- 顶部提供地点搜索框。提交搜索后进入独立的移动搜索结果页；用户可返回地图，并可从每条结果直接添加标点。
- 顶部提供“显示小标题”和“显示路线”两个开关。它们仅影响地图渲染，不更改服务器数据。
- 开关状态以设备偏好存入 `localStorage`，页面刷新和下次访问时恢复。存储值必须经过布尔值解析，缺失或损坏时回退到默认显示。
- 地图浮动操作区提供“地图选点”和“选点连线”按钮；两种模式互斥。

### 地图选点

默认浏览模式下点击地图空白处不创建地点。点击“地图选点”进入选点模式，按钮显示明显的激活与取消状态。该模式中，用户点击地图坐标后打开新增标点抽屉，表单预填经纬度；保存或取消都会退出选点模式。

### 选点连线

点击“选点连线”进入连线模式。此时仅地图标点可被选择：第一次点击记录起点，第二次点击记录终点，然后打开路线确认抽屉。抽屉允许选择交通方式与排序，确认后创建路线。操作完成、取消或主动退出模式都会清空临时起终点。

同一计划内，起点和终点相同的同方向路线只能存在一条。客户端在显示确认抽屉前检查重复路线并提示“路线已存在”；服务端在创建路线时也执行同样校验，作为并发和非 UI 调用的最终保护。反向路线被视为不同路线，可正常创建。

### 地图详情

点击标点打开地点信息抽屉，展示地址、计划时间、备注和待办，并可编辑、删除、导航到下一站。点击地图路线时展示路线信息和导航入口。地点编辑与路线编辑在手机端使用全屏表单或底部抽屉，确保复杂字段在小屏可完整填写。

## 路线、标点与计划管理

### 路线页

显示当前计划的路线列表、交通方式和顺序。每条路线可查看、编辑、删除、打开百度导航。提供“新增路线”和“按标点顺序生成”入口；新增路线使用起点、终点、交通方式和排序的移动表单。重复路线统一按上述规则阻止。

### 标点页

显示当前计划的标点列表、地址和顺序。每条标点可定位查看、编辑、删除、根据下一条路线导航。提供手动新增入口，表单复用现有地点字段；搜索结果和地图选点也使用同一个保存路径。

### 我的页

管理当前用户的旅行计划：选择当前计划、新增、编辑、删除、刷新列表与退出登录。删除计划仍使用明确确认，以避免误删。

## 组件与状态边界

`App.vue` 继续拥有认证、计划、地点、路线和 API 调用状态。为避免桌面和移动模板互相缠绕，拆出以下职责明确的组件或组合逻辑：

- **移动应用外壳**：底部导航、当前移动页面与页面返回栈。
- **地图操作状态**：`browse`、`place-pick`、`route-pick` 三种互斥模式，及连线起点的临时状态。
- **移动抽屉 / 表单**：地点详情、地点编辑、新增地点、路线确认和路线编辑。
- **搜索结果页**：搜索关键字、结果列表、添加动作与返回行为。
- **地图显示偏好**：读取、校验和保存 `localStorage` 中的小标题与路线开关。

`MapView` 接收显示小标题、显示路线和当前地图操作模式等显式 props，只负责地图渲染与将地图点击、标点点击、路线点击事件上报。它不直接调用 REST API，也不自行保存偏好。

## 错误处理与可用性

- 地图尚未初始化或不可用时，保留现有错误提示，禁用依赖地图的操作并避免进入无效模式。
- 没有当前计划时，禁用新增地点、搜索添加与新增路线，并给出建立计划的引导。
- 连线模式中若选择的第二个点与起点相同、或路线重复，保持模式可继续选择并给出清晰提示。
- 删除、退出选点与关闭抽屉不会留下临时地图模式或临时起终点。
- 底部导航、浮动按钮、抽屉和表单为触控优化，保留可读文本或 `aria-label`，并为底部安全区留出空间。

## 验证策略

1. 为地图操作状态新增单元测试：模式互斥、退出后清理临时状态、两次选择构成路线。
2. 为重复路线判断新增单元测试，覆盖同向重复、反向路线和不同计划场景。
3. 为显示偏好新增单元测试，覆盖默认值、持久化与损坏缓存回退。
4. 为后端路线创建接口补充重复路线的集成或路由层测试（若项目现有测试基础允许）。
5. 运行现有前端工具测试与 `pnpm build`，并在桌面及约 375px / 768px 宽度下人工检查：底部导航、抽屉、地图控制、搜索结果、计划管理和所有编辑路径。

## 完成标准

- 手机端可从底部四栏完成查看、搜索、新增、编辑和删除计划、地点与路线。
- 地图操作不会因普通点击误新增地点或路线。
- 小标题与路线可独立开关，并可靠恢复设备偏好。
- 同向重复路线无法通过前端或后端创建。
- 桌面端既有核心操作保持可用，前端构建与相关测试通过。
